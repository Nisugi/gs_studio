# gs_studio review — 2026-09-28

Reviewed through `a2d009f`, including the depth-based sky classification and
clock/repaint changes committed during this review. Review only: no application
code or source artwork changed. Diagnostic programs are under
`target/review-2026-09-28/`.

## Findings

### 1. P2 — Generating a missing map overwrites an existing authored map

Location: `tools/depth_maps.py:138`, `tools/depth_maps.py:153`.

A creature job is queued when either its depth map or normal map is missing.
The write loop then saves both maps unconditionally. Consequently, running
without `--force` replaces a hand-authored depth map when only the normal map
is missing, and vice versa. This contradicts both the documented preservation
rule and the meaning of `--force`.

Verified by executing the actual `main` function extracted with Python's AST,
with inference replaced by a deterministic stub and all files in a temporary
directory. Existing depth bytes changed from `HAND AUTHORED` to `GENERATED`.
No model download or production asset writes were involved.

Fix: decide which outputs may be written individually. If a generated normal
must agree with an existing authored depth, derive it from that depth or report
the mismatch explicitly; silently replacing the authored input is unsuitable.
Add regressions for depth-only and normal-only existing pairs, with and without
`--force`.

### 2. P2 — Same-tier texture loading can resample and degrade the sheet

Location: `crates/gs_field_egui/src/creature_puppet.rs:1407`;
`crates/gs_puppet/src/uv.rs:244`, `crates/gs_puppet/src/uv.rs:321`.

The loader compares the actual longest image dimension with the nominal tier
size to decide whether to resample. However, `UvLayout::fit` approximates the
requested size; it does not guarantee that the resulting dimensions fit inside
that number. A canine sheet at the 2048 tier is 1868 × 2105. At the default
2048 detail setting, the loader therefore resamples it into the identical
1868 × 2105 layout.

That operation is not an identity: surface-address inversion followed by
bilinear sampling can change paint, and unpainted regions are reconstructed.
An isolated release-library reproduction with a synthetic checker texture
changed 381,239 of 2,231,127 painted output pixels (about 17.1%), while the
input and output layouts compared exactly equal. It took about 323 ms in this
one run. The percentage is a synthetic fine-detail sensitivity test, not a
measurement of visible damage to existing paintings.

Other shipped rigs also exceed nominal bounds, including lurk at 1965 × 2304
for tier 2048 and ape at 997 × 1027 for tier 1024. This affects sheets built at
those tiers when loaded, even though no reduction was requested.

Fix: carry the matched nominal tier out of `fit_to`, or compare source and
target layout density before resampling. Return the original texture when the
layouts match. This removes work and preserves the original paint exactly.

### 3. P2 — Texture-detail changes are checked after the pose-cache hit

Location: `crates/gs_field_egui/src/creature_puppet.rs:51`,
`:1340`, `:1536`.

`set_texture_detail` changes an atomic value. Invalidation lives in `texture`,
but `posed_with` returns a cached posed image before reaching that method.
Changing detail while repeatedly drawing an already-cached pose therefore
continues using the old image. It refreshes only after another path calls
`texture` or requests an uncached pose. A still/dead puppet can retain the old
quality indefinitely; animated puppets can update at inconsistent times.

Verified against the release library: build a skinned humanoid pose at 2048,
set detail to 512, and request the same pose. `Arc::ptr_eq` is true. An explicit
`texture` lookup followed by the same pose request makes it false.

Fix: perform detail-generation invalidation before the posed-cache lookup,
or include the detail generation in the pose key. Test the public setter
followed directly by `posed_with`, without an intervening texture lookup.

### 4. P2 — Removed outfit sources leave old installed overrides active

Location: `crates/studio/src/editor/texture.rs:510`;
consumer: `crates/gs_field/src/puppets.rs:543`.

`ship_outfits` copies existing source files but does nothing to destination
files whose source was removed. The authoring loader treats a missing kit as
the shipped kit and missing outfit assignments as no assignments. The runtime
continues reading the previous destination overrides. Saving/installing or
publishing after removing an override can therefore leave different clothing
and geometry in the stage than in the editor.

Verified using the actual `outfits` and `ship_outfits` functions extracted
unchanged into a standalone Rust harness: install the pair, remove the fixture
source pair, then ship again. It reports zero copied files, while both old
destination files remain.

Fix: synchronize the intended resolved state, including removal/defaults.
Simply deleting `outfits.toml` is not sufficient to represent “no outfits” if
the runtime would then fall back to nonempty embedded assignments. Publish an
explicit empty assignment set when that is the author's intended state.
Distinguish genuinely missing files from read errors as well.

## Previous findings and improvements

The earlier atlas-admission issue now has a shared shelf-packing plan; slot
uploads clear their gutters. Skin-image conversion retains the source alpha
and the skin submission uses unit tint. Lamp admission tracks which lamps
entered the pass, with excess lamps kept on the fallback path. UV metadata now
checks layout compatibility beyond dimensions, although unstamped legacy
images intentionally retain the weaker dimension-only check.

Backdrop depth maps are now integrated into the stage. The latest changes
also request redraws for sky animation and completed lighting bakes. These are
meaningful advances over the previous review; they should not remain listed
as wholly missing pipeline features.

## Performance work that can preserve quality

These are implementation opportunities, not measured speedup promises.

1. Fix the redundant texture resampling above first: it has both correctness
   and measurable load-time benefits, with no requested quality tradeoff.
2. Separate posed surface geometry from lighting-dependent results.
   `PosedKey` includes the scene-light key, so changing illumination can rebuild
   the pose, primitive list and surface together. Reuse immutable geometry,
   projection and coverage when only lighting changes; verify output parity.
3. Replace the stage conversion cache's 96-entry FIFO with a byte-budgeted
   cache that tracks usage. `LitImage` holds two RGBA buffers and a float4
   geometry buffer: about 24 bytes per pixel before allocator overhead and
   shared-buffer accounting. Equal entry counts do not imply equal memory use.
   Budget unique allocations and avoid evicting frequently reused poses.
4. Make fallback-only work lazy where profiling warrants it. Posing currently
   builds a primitive list even for skinned drawing, and lighting paths may
   build shadow-caster data that the GPU path does not consume. Preserve the
   fallback behavior when atlas admission fails rather than dropping it.
5. Give immutable skins a stable content/revision identity. The stage currently
   constructs a sampled-byte vector to key skin conversion. An explicit identity
   can avoid that repeated allocation/hash work and make invalidation easier
   to reason about.

Do not reduce texture resolution, shadow sampling or pose fidelity to achieve
these savings. Conservative light/occluder bounds are another option, but need
image-parity tests before claiming that culling preserves quality.

## Pipeline additions

- Record source hashes and builder/model versions for silhouettes, rig,
  clothing, paintings, normal/depth maps and derived sheets. UV metadata
  identifies a layout; it does not establish that a depth map or painting is
  current for the source image. Existing depth maps are currently skipped
  based on existence alone.
- Add atomic file replacement and staged publication of coherent asset sets.
  Several saves and copies still overwrite destinations directly. Validation
  before writing helps, but does not prevent partially published sets on I/O
  failure or interruption.
- Add integration visual cases for atlas pressure, boss outlines, dead tint,
  detail changes, normal-map fallback, dressed skins and view transitions.
  The all-family connected-component audit checks topology, not whether the
  paint, material detail or lighting is visually correct.
- Add production-path performance traces: unique animated skins, cold loads,
  cached frames, daylight changes, atlas repacks, and camera movement. Record
  p50/p95/p99 CPU and GPU costs, allocations, uploaded bytes and cache misses.
  The torchlight benchmark uses a whole-frame callback and repeated images;
  it does not measure the editor's complete per-creature callback path.
- Wire deterministic tests and the asset audit into a checked-in CI/release
  gate. No `.github` workflow was present in this checkout. Include an LFS
  asset-presence check so a pointer file cannot masquerade as usable artwork.
- Wound/status overlays still deserve lighting/geometry integration. Treat
  that as a quality feature requiring its own runtime budget, not a guaranteed
  free improvement.
